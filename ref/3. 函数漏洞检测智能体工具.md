# 函数漏洞检测智能体工具 · 课程要求速查

国科大 2026 年秋季《高级软件工程》大作业。交付一个带图形界面的 LLM Agent，对单个 C/C++ 函数给出漏洞判定与分析报告，并提交全量测试集的预测。[原始课件](3.%20函数漏洞检测智能体工具.pptx)

## 检测流程与界面（第 3–7 页）

1. **输入**。用户在图形界面输入一个 C/C++ 函数及其修复提交链接，或上传 `.jsonl` 文件启动批量检测。
2. **先检索，再初判**。Agent 从课程历史 CVE 知识库检索相似案例，结合待测函数找出可疑点。
3. **按需读仓库**。初判证据不足时，Agent 自主决定从对应版本快照读取哪些上下文，例如调用方、被调用方、全局变量、类型、宏或辅助函数。
4. **展示与报告**。界面实时展示历史案例检索和仓库读取记录。每份报告包含函数 `idx`、有漏洞或无漏洞的判定、判定理由、分析记录。

## 数据与工具边界（第 5、6、8、10 页）

| 对象 | 要求 |
|---|---|
| 历史知识库 | 仅用课程提供的数据，允许成对使用历史漏洞版和修复版。可用 `cve_desc`、`commit_message`、`cwe`、`project`、`file_name` 等字段，可直接索引或由 LLM 总结。禁止补充外部安全知识。 |
| 测试样本 | 150 对、共 300 条，每对为同一函数的漏洞版和修复版。字段为 `idx`、`commit_url`、`target`、`func`。每次推理只给其中一个函数及其对应快照。 |
| 快照与联网 | `target=1`（有漏洞）取修复提交的**父提交**，`target=0`（无漏洞）取**修复提交本身**。禁止向模型提供 git diff 或两版变更信息。除按 `commit_url` 获取指定版本仓库外，禁止提供网络搜索能力。 |
| Agent 自主性 | 必须基于 Agent 框架自主推理和调用工具。禁止用 skill 包装 Codex、Claude Code 等商业代码分析智能体，也禁止将检测做成无自主决策的多步 LLM API 串行调用。 |

技术选型由团队决定。课件举例包括 LangGraph、Pi Agent、AutoGen（Agent 框架），LangChain、LlamaIndex、FAISS、Chroma（检索），以及 GitHub API、Tree-sitter（快照与代码解析）。

## 提交与评分（第 8–9 页）

提交 `result.jsonl`，每个测试样本一行，共 300 行。每行仅含 `idx` 和整数 `prediction`（1 有漏洞，0 无漏洞），例如 `{"idx":42,"prediction":0}`。

| 类别 | 漏洞版预测 | 修复版预测 | 含义 |
|---|---:|---:|---|
| P-C | 1 | 0 | 两版均正确 |
| P-V | 1 | 1 | 修复版误报 |
| P-B | 0 | 0 | 漏洞版漏报 |
| P-R | 0 | 1 | 两版均判反 |

按 **P-C 对数**定基础等级。A 为 30 对及以上，B 为 25–29 对，C 为 20–24 对，D 为 0–19 对。若 **P-R > P-C / 2**，最终等级降一级，最低为 D。恰好等于一半时保留基础等级。
