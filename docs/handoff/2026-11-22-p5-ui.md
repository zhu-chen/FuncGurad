## 2. 做了什么

### 2.1 后端 HTTP 层（`backend/api/`、`backend/server.py`）

| 方法 | 路径 | 说明 | 状态码 |
|---|---|---|---|
| GET | `/api/health` | provider、数据集规模、运行目录 | 200 / 503 |
| GET | `/api/pairs?limit=30` | 相邻配对列表，供前端选择 | 200 |
| GET | `/api/runs?limit=20` | 最近运行列表 | 200 |
| POST | `/api/runs` | 提交单条；`{idx, pair}`，自动补齐配对 | 202 / 400 / 422 / 503 |
| GET | `/api/runs/{run_id}` | 运行状态、类别、是否已有报告 | 200 / 404 |
| GET | `/api/runs/{run_id}/report` | `report.json` + `result.jsonl` + 产物路径 | 200 / 404 / 409 |
| GET | `/api/runs/{run_id}/trace?after=N` | 轨迹增量读取；`after` 是已收到的事件条数 | 200 / 404 |
| POST | `/api/batches` | 批量提交；`{idx_list, pair}` | 202 / 400 / 422 / 503 |
| GET | `/api/batches/{batch_id}` | 批量状态与逐条结果 | 200 / 404 |
| GET | `/` | 托管 `web/dist` 单页 | 200 / 503 |

统一响应：

```json
{"ok": true, "data": {...}, "error": null}
{"ok": false, "data": null, "error": {"code": "404", "message": "run_id=... 不存在"}}
```

- 参数校验错误返回 422；未知 run/batch 返回 404；报告未完成返回 409；显式选择真实 provider 但缺 key 返回 503。
- 单条与批量都在后台线程执行，接口立即返回，前端通过轮询获取状态与轨迹。
- 每次运行落盘到 `cache/runs/<run_id>/`：`result.jsonl`、`report.json`、`trace.jsonl`。
- 批量按提交顺序串行执行，单条失败记录为 `failed`，不阻塞后续条目。

### 2.2 前端（`web/`）

Vue3 + Vite 单页，三个区域：

| 区域 | 内容 |
|---|---|
| 输入区 | 填 idx 运行单条；下拉选择一对样本；批量 textarea；批量列表与逐条状态；最近运行 |
| 实时轨迹区 | 按时间顺序展示 `run_start / llm_step / repo_tool / decision / run_end / error`；显示序号、类型、工具名、耗时；点击某步展开原始事件 JSON（含工具参数与返回摘要） |
| 报告区 | P-x 类别、两版 prediction、每条样本的 verdict、理由、证据门控、证据文件路径、工具调用轨迹、`result.jsonl` 两字段记录、report.json 原始内容 |

关键交互：

- 运行开始后每 700ms 轮询 `/trace`，用 `after=已收到条数` 增量追加，不重复渲染。
- 批量任务每 1000ms 轮询 `/batches/{id}`，逐条状态更新；点击“查看轨迹”切换到该条 run。
- 所有请求统一走 [api.js](file:///e:/软件工程/FuncGurad/web/src/api.js)，统一解包 `{ok,data,error}`，对 400/404/409/422/500/503 给出可读提示，并有超时与网络错误提示。
- 前端不做任何 P-x 计算、预测或门控判断，只展示后端报告。

## 5. 没做什么 / 已知限制

- 仍只有 stub provider；真实 OpenAI 兼容 provider 的界面表现与检测质量未验证。
- 轨迹使用轮询（700ms），未做 SSE/WebSocket；满足“实时看到步骤”，但不是推送模型。
- 任务状态保存在进程内存；服务重启后“最近运行”“批量列表”会清空，但 `cache/runs/` 下的产物仍在。
- 批量任务串行执行，未做并发池、取消或重试；单条失败只记录，不自动重跑。
- 没有登录鉴权、限流和运行目录清理策略；当前定位是本地单机演示。
- 前端只覆盖桌面与窄屏自适应，未做移动端专门优化。
- 没有前端单元测试；验证以 API 实跑与浏览器手工/自动化检查为主。

## 6. 踩坑与约束

1. **`dist/` 被全局忽略**：根 `.gitignore` 有 `dist/`，需要显式 `!web/dist/` 与 `!web/dist/**` 才能提交构建产物。
2. **`seq` 是每个 run_id 内递增**：一次配对运行里有两条样本，`trace.jsonl` 中会出现两组从 0 开始的 seq；轨迹接口因此用“已收到条数 after”而不是 seq 做增量游标。
3. **报告未完成要返回 409**：前端在状态为 `done` 后才拉报告；提前请求会得到可读的“尚未完成”提示。
4. **前端不做业务判断**：P-x、prediction、门控都由后端报告给出，前端只渲染。
5. **node_modules 不入库**：`web/.gitignore` 已忽略；`package-lock.json` 入库保证可复现。
6. **key 不落盘**：provider 配置仍只从环境变量读取；界面只展示 `is_stub` 与模型名。
7. **一条命令启动**：`python -m backend.server` 依赖已安装的 FastAPI/uvicorn；首次需 `pip install -r requirements.txt`。
8. **静态资源路径**：FastAPI 挂载 `/assets` 并返回 `web/dist/index.html`；若重新构建，文件名哈希会变化，但 index.html 会同步更新。
