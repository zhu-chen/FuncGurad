# P7 全量评测（GLM-5.3-Flash，300 条）

- 日期：2026-11-24
- 状态：已完成
- 关联：README「全量评测」、「当前进度」；P6 真实模型接入

## 1. 目标

在课程测试集上跑完 300 条样本（150 对），使用真实模型 GLM-5.3-Flash，
输出官方要求的 `result.jsonl`（只含 `idx` / `prediction`），并按官方相邻配对口径
统计 P-C / P-V / P-B / P-R 与等级。

## 2. 数据与运行设置

| 项 | 值 |
|---|---|
| 测试集 | `dataset/test.jsonl`，300 条 / 150 对 / 43 个来源仓库 |
| 知识库 | `dataset/knowledge.jsonl`；审计后 7,497 条入索引，残余泄漏 0 对 |
| 模型 | `glm-5.3-flash`，`https://open.bigmodel.cn/api/paas/v4` |
| Agent 设置 | 最多 10 步；单样本总超时 900 s；单请求 180 s；输出上限 16,384 tokens |
| 推理设置 | SSE 流式；`reasoning_effort=low`；`clear_thinking=false`；失败重试 2 次 |
| 工具 | `find_files` / `grep_content` / `read_file` / `search_knowledge` |
| 快照缓存 | `D:\FuncGuardCache`（C 盘空间不足，快照放 D 盘；产物不入库） |

## 3. 方法

1. 按仓库分组准备快照：blobless clone → fetch 指定 commit → 解析父提交 → `git archive`。
2. 每跑完一个仓库，删除该仓库的快照与 git 克隆，控制磁盘峰值。
3. 逐样本运行 Agent；每完成一条原子写入 `predictions.jsonl` / `status.jsonl`，支持断点续跑。
4. 最后一步禁用工具并强制模型输出最终 JSON；证据必须能在快照中复核，否则证据门控降级为 benign。
5. 对 commit 不可达或 GitHub 返回 429 的仓库，使用 `--synthetic-fallback`：
   把数据集提供的函数文本写成 `func.c` 合成快照继续评测，状态记录 `synthetic_snapshot=True`。
6. 汇总后同时运行 `bench.score` 与官方 `dataset/evaluation.py`，两者结果一致。

## 5. 覆盖率与失败处理

- 300 条预测全部生成；真实仓库快照 194 条，合成函数文本快照 106 条。
- 合成快照主要分布：
  - TensorFlow：65 条
  - mruby：12 条
  - linux：8 条
  - glewlwyd / barebox：各 4 条
  - flatpak：3 条
  - uWebSockets / postgres / weechat / vim / owntone-server：各 2 条
- 主要原因是 GitHub 返回 `429 Too Many Requests`，以及部分 commit 已不可达（codeload 404 / `git fetch` 128）。
- 第一轮还出现过“样本元数据存在但快照目录已被清理”的问题，已在驱动中加入
  `_snapshot_ready()` 检查；同时准备超时时会杀掉整棵 git 进程树。

## 6. 复现

```powershell
# 1. 准备测试集与知识库
#    默认读取 dataset/test.jsonl、dataset/knowledge.jsonl
python -m knowledge.audit_leakage --knowledge dataset/knowledge.jsonl --test dataset/test.jsonl --threshold 0.5
python -m rag.build_index --knowledge dataset/knowledge.jsonl
python -m knowledge.audit_leakage --cards --threshold 0.5

# 2. 跑全量（真实快照优先，失败用合成快照）
python scripts/run_full_eval.py --cache D:\FuncGuardCache --synthetic-fallback

# 3. 查看结果
python scripts/eval_progress.py
```

结果文件：

- `D:\FuncGuardCache\eval\full-result.jsonl`：官方格式结果（`idx` + `prediction`）
- `D:\FuncGuardCache\eval\eval-report.json` / `official-evaluation.txt` / `summary.json`
- `D:\FuncGuardCache\eval\status.jsonl`：逐样本状态、步数、是否合成快照
- `D:\FuncGuardCache\eval\real-only-result.jsonl` / `real-only-report.json`：真实快照子集
- 仓库内副本：`cache/runs/full-eval/`（`cache/` 不入库）

## 7. 限制

- 这是一次单轮运行，没有多随机种子重复，不报告方差。
- 106 条使用合成函数文本快照，不是真实仓库快照；全量分数包含这些样本，
  真实快照子集（94 对）单列如上。
- 未做逐样本人工复核；P-C 55 / P-R 8 等结果仍可能存在模型误判。
- 评测成本与耗时明显高于 stub：本轮实际运行约 6 小时（含快照准备、限流重试），
  单样本最长接近 5 分钟。
- 结果依赖 `dataset/` 课程数据与模型服务可用性；仓库不包含数据与 API key。
