# 交接：P2 仓库快照链路（feat/p2-snapshot）

- 分支：`feat/p2-snapshot`
- 基线：`main` @ `48da430`（P1 已通过 PR #1 合并）
- 日期：2026-11-22
- 范围：只做快照与定位的数据通路，不接 Agent、不做检索

## 做了什么

1. 实现 `commit_url` 解析：
   - GitHub 标准提交链接。
   - qemu 非标准链接（`?p=qemu.git;a=commit;h=...`，注意查询串用分号分隔）。
   - 其他域名统一标记为 `manual`，批处理不中断。
2. 实现原生 git 客户端（不依赖 `gh`）：
   - `clone --filter=blob:none --no-checkout`，每个仓库只克隆一次。
   - 按 commit SHA `fetch`，提交已存在时跳过。
   - `target=1` 用 `rev-parse "<sha>^1"` 回溯第一父提交，`target=0` 用提交本身。
   - `git archive` 导出 tar，再用标准库安全解压到 `cache/snapshots/`；快照目录不含 `.git`。
   - 所有网络型 git 命令注入 `http.lowSpeedLimit/lowSpeedTime`，连接停滞时主动失败，不无限挂起。
3. 网络受限兜底（默认开启，`FUNCGUARD_ARCHIVE_FALLBACK=none` 可关闭）：
   - 主链路克隆/取 SHA 失败时，改用 `git fetch --depth=1 --filter=blob:none origin <sha>` 只取单个提交，
     从提交对象的 `parent` 行读取第一父提交（浅仓库里 `rev-list` 会把父提交隐藏，不能用于此判断）。
   - blob 拉取失败或超时时，改用 `https://codeload.github.com/{owner}/{repo}/tar.gz/{sha}` 直连取同一提交的树，
     显式绕过代理，解压时剥掉 `{repo}-{sha}/` 顶层目录。
   - 走兜底的样本 `method` 记为 `manual`（`RepoSnapshot` 契约中 `manual` 用于非 GitHub 或网络受限样本），
     并在快照标记的 `note` 里记录触发原因。
   - 同一仓库首次失败后，本进程内不再尝试 git，后续样本直接走兜底，避免每对样本都等一次超时。
4. 快照去重与元数据：
   - 快照目录按 `repo + resolved_commit` 命名，同一版本只导出一次。
   - 每个样本写 `cache/meta/samples/{idx}.json`，字段符合 `RepoSnapshot` 契约。
   - 每个快照写 `cache/meta/snapshots/{repo}__{sha}.json` 完成标记。
5. 函数定位 v1：
   - 用函数文本前 240 个规范化字符做探针，命中后再用完整规范化文本确认。
   - 只扫描常见 C/C++ 源码后缀，跳过二进制、超大文件和 `.git`。
   - 输出 `found` / `partial` / `not_found`、相对路径、置信度、扫描文件数。
6. 批量准备：
   - `python -m repo_service.prepare` 支持 `--only-idx`、`--limit`、`--workers`、`--plan-only`、`--no-locate`。
   - 逐条打印并实时写 manifest；单条失败只记录，不中断整批。
   - 同一仓库的 clone/fetch/archive 串行，不同仓库按 `--workers` 并发。

## 怎么验证

以下命令均在仓库根目录执行，且需要本地代理。常用环境变量（全部有默认值，可不设）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `FUNCGUARD_GIT_PROXY` | `http://127.0.0.1:7897` | git 命令走的代理 |
| `FUNCGUARD_MAX_WORKERS` | `2` | 批处理并发（按仓库串行，避免拉爆网络） |
| `FUNCGUARD_GIT_TIMEOUT` | `900` | clone/fetch 总超时（秒） |
| `FUNCGUARD_GIT_LOW_SPEED_LIMIT` / `_TIME` | `1000` / `30` | 低于 1000 B/s 持续 30s 判定停滞并放弃 |
| `FUNCGUARD_GIT_ARCHIVE_TIMEOUT` | `180` | 单次 `git archive` 超时（秒） |
| `FUNCGUARD_ARCHIVE_FALLBACK` | `codeload` | 网络受限兜底；`none` 表示只用 git 链路 |
| `FUNCGUARD_CODELOAD_TIMEOUT` | `1800` | codeload 兜底下载超时（秒） |

```powershell
# 0. 数据集与目录准备
# cache/dataset/test.jsonl 需已存在（P1 阶段复制，cache/ 已忽略）
New-Item -ItemType Directory -Force cache/meta | Out-Null

# 1. 300 条 URL 分类，不下载，验证批处理能连续输出
python -m repo_service.prepare --plan-only --manifest cache/meta/plan.jsonl

# 2. 实际准备指定样本（至少 5 条，含 TensorFlow、target=1、qemu 兜底）
python -m repo_service.prepare `
  --only-idx 194994 --only-idx 218852 `
  --only-idx 194989 --only-idx 218785 `
  --only-idx 195017 --only-idx 187732 `
  --workers 2 --manifest cache/meta/verify.jsonl

# 3. 检查单条快照
#    - 目录存在
#    - 无 .git
#    - target=1 的 resolved_commit 等于 git rev-parse "<requested>^1"
Get-ChildItem cache/snapshots -Directory | Select-Object Name
Get-ChildItem cache/snapshots -Directory | ForEach-Object {
  "$($_.Name) has_git=$([bool](Test-Path (Join-Path $_.FullName '.git')))"
}
```

判定标准：

- manifest 中 `status=snapshot_ok` 的样本，`snapshot_dir` 存在且无 `.git`。
- `target=1` 的 `resolved_commit` 必须等于请求提交的第一父提交。
- `target=0` 的 `resolved_commit` 等于请求提交本身。
- qemu 样本 `status=manual_pending`，有 `reason`，不抛异常。
- 同一仓库多个样本只出现一次 `cache/git/{owner}__{repo}`。

## 踩坑与禁区

1. **代理**：本机直连 `github.com:443` TLS 失败，必须在命令上带 `http.proxy=http://127.0.0.1:7897`。`Settings.from_env()` 默认读取 `FUNCGUARD_GIT_PROXY`，不要把代理写进仓库配置。
2. **凭证**：快照链路只访问公开仓库，不需要 token；不要为了省事把 token 传给 `git clone` 或写进 URL。
3. **缓存**：所有克隆、tar、快照、manifest 都在 `cache/`，已被 `.gitignore` 忽略；不要提交。
4. **qemu URL**：查询串用分号分隔，`parse_qs` 默认按 `&` 解析会拿不到 `h`，必须用正则或先替换分隔符。
5. **git archive 会触发懒加载**：blobless 克隆执行 `archive` 时会自动 `fetch` 缺失 blob，首次导出较慢，属正常现象；不要中途删缓存目录。
6. **代理实测很慢**：本机经 `127.0.0.1:7897` 访问 `github.com` 只有约 28 KB/s，拉 TensorFlow 的 blob 不现实；`codeload.github.com` 直连约 5.7 MB/s。因此兜底默认走 codeload 直连，`method` 记为 `manual` 并在 `note` 说明原因，不要误以为快照是纯 git 导出的。
7. **超时必须杀进程树**：`git archive` 会派生子进程（`fetch`、`index-pack`），只杀父进程会留下持有管道的孤儿子进程，Python 端会永久卡在 `communicate()`；已改为 `taskkill /F /T`。自己写类似封装时不要用裸 `subprocess.run(timeout=...)`。
8. **浅仓库不能用 rev-list 取父提交**：`fetch --depth=1` 会把提交标记为 shallow，`rev-list --parents` 会把父提交隐藏；必须 `git cat-file -p <sha>` 读 `parent` 行。
9. **大仓库**：TensorFlow 的 clone/archive 体积与耗时远大于其他仓库；批量时控制 `--workers`，避免 43 个仓库同时拉爆网络。
10. **符号链接**：安全解压只写普通文件与目录，符号链接会被跳过并在快照标记中记录数量；不要依赖快照中的链接路径。
11. **定位口径**：v1 只做规范化文本匹配，不做语义匹配；`partial` 只代表探针命中，不能当作确定定位。
12. **分支纪律**：只向 `feat/p2-snapshot` 提交；禁止直接推 `main`，禁止 force push。
13. **只读 pack 文件**：git 的 pack 是只读的，Windows 下直接 `shutil.rmtree` 会抛 `WinError 5`；清理半成品克隆必须先去只读位（`_force_rmtree`）。
14. **本地查询会触发懒加载**：blobless 仓库里 `git cat-file -e <sha>` 可能去远端补对象，表现为卡死；本地判断提交是否存在必须带 `GIT_NO_LAZY_FETCH=1`（`run_git(no_lazy_fetch=True)`）。
